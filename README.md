# MG6
1. I believe that if a for loop is run within Update(), it will complete in its entirety before Update() finishes, therefore causing lag if one writes a particularly complicated/long for loop. I believe this is the case as it wouldn't make much sense for it to execute over multiple frames if there is code to be run in Update() placed after the for loop - if the for loop executes over multiple frames, when would code placed after that loop run? It seems only logical to assume that the entirety of Update(), including lengthy for loops, will be completed in one frame, even if it induces lag.
2. A potential issue that I found is that when jumping through a platform/the ground, the player is able to stay within the ground walls/platform for the entire time they are moving upwards. Once they reach the peak of their height (essentially causing the positive linear velocity condition for the if-statement responsible for disabling the player's collider to be false), their collider is re-enabled. However, since they are still positioned within the platform/ground, the game quickly repositions them to any given side of the platform/ground tile. This can allow for the player to easily clip out of bounds when this technique is performed on the walls/ceiling.
